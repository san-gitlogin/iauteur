# Critic Checklist — run silently before emitting ANY spec; fix all violations
1. Scene 1 is HOOK, ≤8s, states stakes, no greeting.
2. Every atWord ≥1 and ≤ that scene's narration word count.
3. Every element named in narration has an anchor; every anchored element is named.
4. All text fields within budgets (text_budgets.md). Count characters, don't guess. Badges inside cards use the SMALLER in-card budget.
5. Every headline: exactly one [accent]; brackets balanced.
6. Colors only from the semantic set, used by MEANING.
7. Studio scenes have a source footer ≤64 chars.
8. durationFrames ≈ words×12+30 (±40%).
9. One theme for the whole video; theme fits topic mood; different from the previous video's theme when possible.
10. Numbers spoken = numbers shown. No stat in narration without a visual.
11. RECAP answers the hook's open loop. OUTRO ≤5s.
12. No invented quotes from real people. No unverifiable claims stated as fact.
13. Scene types exist in the registry. IDs unique, s01…sNN in order.
14. Visual change every 2.5–4s: no scene where nothing enters/moves for >4s (check anchor gaps).
15. Imagine each frame at 120px wide (thumbnail test): is the hierarchy still obvious?
16. Imagine every scene at BOTH 1920×1080 and 1080×1920 — text budgets are set by the NARROWEST container (see design_contract.md).
17. Confirm the topic is one the operator understands; if the source is niche (e.g. a specific coin, protocol, or tool), open the video by defining it in one sentence — never assume viewer OR operator knowledge.
